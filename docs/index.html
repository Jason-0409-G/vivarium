工作流概览

将研究目标转换为具有显式产物与验收条件的分析流程

对使用者而言，完整流程由分析规划、资源路由、工具执行、证据提交与状态恢复五个阶段构成。

  1. 01

    分析规划

    依据研究目标定义阶段顺序、输入对象、工具需求、依赖关系与预期产物。

    执行前可审阅
  2. 02

    资源感知路由

    探测 CPU、内存、已安装工具与集群调度器，据此选择本地执行、集群作业脚本或外部执行命令。

    形成显式路由决策
  3. 03

    执行与产物校验

    在隔离进程中调用生物信息学工具，并检查退出状态、标准输出、标准错误与预期产物。

    失败或空产物不提交
  4. 04

    证据记录与阶段提交

    将产物、精确命令、工具版本与校验记录绑定到阶段，并在通过提交闸门后追加写入事件日志。

    计算结论可追溯
  5. 05

    基于事件日志的状态恢复

    从已验证事件重建流程状态，对已提交阶段保持幂等，并从首个未完成阶段继续执行。

    避免重复执行已提交阶段
设计依据

脚本执行、产物有效性与流程可恢复性是相互独立的工程属性

✓

提交前验证

进程正常启动并不等同于阶段成功。仅当退出状态、预期产物与持久化证据均满足约束时，阶段方可提交。

↻

确定性状态恢复

流程状态由同一仅追加事件日志按字节重建；已提交阶段保持幂等，恢复过程不重复执行这些阶段。

⌁

产物驱动的结果复述

结果汇报读取已经校验并密封的计算产物与事件记录，不以语言模型的会话记忆作为数值依据。

⇄

显式执行边界

资源可容纳的阶段可在本地执行；计算密集型阶段生成可审计的集群作业脚本。当前版本不自动提交或轮询集群作业。

核心观点

记忆漂移是项目级状态管理问题，而非模型上下文能力的局限

在大规模、异构、多来源的项目数据上，持续编写与更新 handoff 文件并不能消除跨阶段的记忆漂移。交接文档本身随项目增长而膨胀，摘要、遗漏与转录误差在多次交接中累积。

其根本原因不在于模型的上下文管理能力，而在于项目级的状态管理。随着累积上下文长度增加，模型可靠复述既有计算结果的能力下降，记忆漂移随之加剧；更换更强的模型并不能消除这一效应，因为待保存的状态超出了任何单个上下文窗口可携带的容量。

vivarium 将正确性关键的状态外置到仅追加事件日志。结果复述由此转化为对已密封产物的读回，其保真度与上下文长度无关，也与所用模型的规模无关。

  • 项目端，而非模型端漂移源于外部状态未被持久固定，而非模型推理能力不足。
  • 随规模恶化累积状态超出可携带上下文后，凭记忆的复述保真度急剧下降。
  • 读回替代回忆从已密封事件日志读回，使保真度不再依赖上下文长度。

技术机制

流程状态写入仅追加事件日志，而不是留在模型记忆里

下面的机制图展示 PLAN、ROUTE、EXECUTE、VALIDATE、C-1 GATE、SEAL 与 RECOVER 如何组成一个可恢复闭环。

展开内部协议与实现边界

仅追加事件日志

受限 RFC 8785/JCS 规范化 JSON、域分隔 SHA-256 摘要和仅追加 JSONL；未完成尾行会被隔离。

C-1 提交闸门

证据包、成功完成记录、quorum pass 和完成证明必须全部一致，失败或空产物不得密封。

确定性恢复

指由同一事件日志按字节重建流程状态，不承诺不同系统、硬件或工具版本产生位级一致的分析结果。

CC Switch

在同一客户端中管理并切换多家模型 API

CC Switch 是可选的供应商配置与本地协议路由工具，不是 vivarium 的运行依赖。它可管理预设或自定义 API 供应商；DeepSeek 仅作为配置示例，不代表 vivarium 绑定或推荐某一模型。

从 CC Switch 官方 Releases 获取 ↗
  1. 1. 安装并启动客户端先按上述步骤安装 Claude Code 或 Codex，并至少启动一次。
  2. 2. 创建供应商配置在 CC Switch 中选择预设或填写自定义 endpoint、模型名和 API key；密钥不得写入仓库、截图或共享文档。
  3. 3. DeepSeek 示例Claude Code 可使用 DeepSeek 的 Anthropic 兼容端点；Codex 使用 Responses API，当供应商仅提供 Chat Completions 时，需在 CC Switch 中启用 Codex 本地路由进行协议转换。
  4. 4. 重启并验证切换配置后重启对应客户端，核对当前模型与端点，再安装 vivarium。
